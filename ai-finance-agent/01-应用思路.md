# 问题一：AI + 金融，有哪些值得做的 Agent 应用？

> 本文回答“有什么好想法”。判断标准不是“技术上新不新”，而是“在真实金融业务里是否可落地、可衡量、可审计”。
> 引用编号对应 [`04-参考来源.md`](04-参考来源.md)。

## 0. 先立判断标准：什么样的场景值得做成 Agent？

金融业务对错误、合规、可解释性的容忍度远低于一般消费场景。一个场景适合 Agent，通常同时满足：

1. **高频且耗时**：每天/每周重复发生，单次需要 30 分钟以上的人工处理。
2. **输入以文档和数据为主**：合同、年报、公告、政策、工单、流水、财报。
3. **输出可核验**：能追溯到原文段落、数据字段、计算过程或业务规则。
4. **错误可被拦截**：有人审、有阈值、有回滚，不直接触发资金划转、授信审批或交易。
5. **监管允许“辅助”**：定位是 copilot / analyst assistant，而不是替代持牌人员做最终决策。

反过来，以下场景不适合作为第一批落地目标：全自动交易、无人工复核的授信/理赔决策、没有出处的“万能金融问答”、以及需要跨多个核心系统写入的高权限操作。

## 1. 投研与财报研究助理（Research Copilot）

麦肯锡将 Agentic AI 视为银行价值链重塑的重要机会[7]；但机会能否兑现，取决于场景是否满足下面的判断标准。

**做什么**：用户给出公司、行业或问题，Agent 自动检索年报/季报、公告、招股书、研报、新闻与宏观数据，抽取财务指标，调用计算工具做同比/环比、估值与敏感性分析，最后生成**带引用的**研究初稿、对比表和风险清单。

**Agent 形态**：规划器 + 文档检索（RAG）+ 表格解析 + 行情/财务数据工具 + Python 计算沙箱 + 引用校验 + 写作模板。

**为什么适合 Agent**：投研是典型的“多源资料 + 多步推理 + 大量写作”任务，传统搜索只能给链接，RPA 只能搬运数据；Agent 可以把“找—算—写—核”串起来。

**关键设计**：
- 每个结论必须绑定来源（文档、页码/段落、数据字段、访问时间）；无来源的句子不允许进入“事实”区。
- 数字一律由工具计算，LLM 只负责解释；对同一指标做多源交叉校验。
- 明确 **as-of 日期**，避免把后来发生的信息用于历史分析（前视偏差）。
- 区分“事实 / 一致预期 / 模型推断”，并在版式上分开呈现。
- 研报与数据库有版权和授权限制，检索源要合法合规。

**价值指标**：初稿耗时、引用准确率、人工修改比例、覆盖标的数量。具体提升幅度必须以本机构试点度量，不宜直接套用厂商宣传数字。

**主要风险**：幻觉与错误归因、数据授权、观点合规、把“生成”误当“研究结论”。

## 2. 信贷尽调与授信报告 Agent

**做什么**：根据授信申请材料，自动完成材料清单核对、财务报表抽取、现金流与偿债指标计算、关联方与舆情检索、授信政策匹配，生成尽调报告初稿和缺失材料清单，供客户经理与审批人修改。

**Agent 形态**：材料解析（PDF/Excel/扫描件）+ 规则引擎（准入、额度、集中度）+ 外部数据工具 + 报告生成 + 人工签批节点。

**为什么适合 Agent**：信贷尽调的核心痛点不是“不会写”，而是材料多、口径多、政策更新快、重复劳动多；Agent 可以把“找材料、对口径、算指标、套政策”标准化。

**关键设计**：
- 规则引擎负责硬约束（年龄、行业、额度、集中度），LLM 负责抽取、归纳与解释，二者职责分离。
- 每个结论引用具体材料与条款；缺失项显式列出，不允许模型“补全”。
- 保留完整审计轨迹：谁在什么时候改了什么、依据是什么。
- **合规提示**：欧盟《人工智能法案》将“评估自然人信用状况/信用评分”的 AI 系统列为高风险（欺诈检测除外），对生命/健康保险的风险评估与定价同样属于高风险。[5] 若涉及个人信贷或保险，必须按高风险系统做风险管理、数据治理、技术文档与人工监督。

**价值指标**：单笔尽调工时、补件轮次、审批退回率、报告一次通过率。

**主要风险**：把“辅助报告”做成“自动审批”、材料造假识别不足、模型偏见与可解释性不足。

## 3. 反洗钱（AML）与反欺诈调查 Agent

**做什么**：对交易监控警报做初筛与优先级排序，做实体识别与关联网络分析，汇总客户画像、历史行为与公开信息，生成可疑活动报告（SAR）草稿和调查建议，由调查员复核提交。

**Agent 形态**：多工具调查助手（账户/交易/客户画像/名单/网络图谱）+ 多 Agent 并行调查（可选）+ 证据链 + 报告模板 + 人工决定。

**为什么适合 Agent**：警报量大、误报多、调查过程高度重复，且需要跨系统拼接证据；这正是“工具调用 + 归纳 + 写作”擅长的部分。德勤的行业观察把 AML 列为 Agentic AI 的典型用例，描述了多 Agent 并行调查的模式；其客户案例中法务合同 Agent 的 92.9% 准确率属于来源方自述，应视为案例而非独立基准。[8] 英国央行/FCA 调查也显示，AML 与反欺诈是当前 AI 感知收益最高的领域之一。[3]

**关键设计**：
- 证据链可追溯：每条判断对应交易、名单命中、公开记录或客户历史。
- 只做“调查建议”，不自动冻结账户、不自动提交监管报告。
- 误报率与漏报率同时监控；对模型/规则变更做回溯测试。
- 注意数据最小化与跨境数据传输限制。

**价值指标**：警报处理量、平均调查周期、误报率、SAR 质量与退回率。

## 4. 合规政策与监管变更 Agent

**做什么**：把外部监管规则、内部制度、控制措施建成可检索的知识库；当新规发布时，自动做条款级比对、影响分析、差距清单和整改建议，生成带引用的合规备忘录。

**Agent 形态**：监管语料 RAG + 条款/义务抽取 + 制度映射 + 差异分析 + 引用校验 + 合规官签核。

**为什么适合 Agent**：合规工作的瓶颈是“读得全、对得准、跟得上”，而监管文本更新频繁、跨法域差异大；Agent 可以把“检索—比对—起草”做成流水线。

**关键设计**：
- 版本与生效日期是核心元数据；必须能回答“当时有效的版本是什么”。
- 法域、行业、业务线多维过滤；引用到条款号。
- 合规官对最终判断负责；Agent 输出标注“待确认项”。
- 与内部制度库、控制矩阵、审计发现打通，而不是只做问答。

**价值指标**：新规响应时间、条款覆盖率、遗漏率、整改闭环周期。

## 5. 运营对账与支付异常处理 Agent

**做什么**：对账差异识别、异常分类、根因定位、工单草拟与分派；对常见差异给出处理建议，对高风险差异升级人工。

**Agent 形态**：确定性匹配引擎 + 异常分类器 + 知识库检索 + 工单工具 + 人工复核。

**为什么适合 Agent**：这是“低风险、高频、规则明确”的场景，最容易量化 ROI；LLM 的价值在于处理非结构化备注、解释差异、生成工单，而不是替代匹配算法。

**关键设计**：
- 金额、账户、状态等关键字段用确定性逻辑处理；LLM 不直接改账。
- 只读优先、白名单写入、金额阈值、双人复核、幂等与回滚。
- 异常处理建议要引用历史相似案例与操作手册。

**价值指标**：自动匹配率、异常平均处理时长、差错率、升级率。

**建议**：如果只能先做一个场景，优先选它——风险最低、指标最清楚、最容易在 8–12 周内证明价值。

## 6. 客服与投顾辅助 Agent（Agent Assist）

**做什么**：实时总结客户来电/对话、检索产品与政策、生成回复建议与下一步行动（next best action）、识别投诉与合规风险并转人工；面向投顾时，辅助做客户画像、产品匹配与适当性检查。

**Agent 形态**：坐席辅助（不直接对客）+ 知识库 RAG + 客户/账户工具（只读）+ 合规检查 + 转人工。

**为什么适合 Agent**：客服高频、知识更新快、培训成本高；辅助模式可以在不改变持牌责任的前提下降低平均处理时长。

**关键设计**：
- 明确“辅助坐席”而非“自主给投资建议”；投资建议、适当性判断由持牌人员负责。
- 敏感信息脱敏、通话/对话留痕、可回溯。
- 建立“禁止话术”和升级规则；对投诉、舆情、监管关键词强制转人工。

**价值指标**：平均处理时长、一次解决率、转人工率、合规抽检合格率。

## 7. 量化研究与回测 Agent（探索型）

**做什么**：把自然语言研究假设转成代码，在沙箱中取数、回测、画图、生成研究报告；对数据泄漏、幸存者偏差、交易成本做自动检查。

**Agent 形态**：代码生成 + 沙箱执行 + 数据目录 + 回测引擎 + 结果核验。

**为什么适合 Agent**：研究迭代快、代码重复多；但金融数据有强烈的时点性和口径问题，必须把“可复现”放在第一位。

**关键设计**：
- 严格 as-of 数据访问，禁止未来函数；回测结果附带数据版本、参数、成本假设。
- 沙箱隔离、资源限额、代码审计；不接实盘交易。
- 对过拟合做提示，但不替代研究员的判断。

**价值指标**：研究迭代周期、结果复现率、代码返工率。

## 8. 优先级矩阵与组合建议

| 场景 | 业务价值 | 落地难度 | 合规/错误风险 | 建议 |
|---|---|---|---|---|
| 运营对账/支付异常 | 中高 | 低 | 低 | **首批试点** |
| 投研/财报研究助理 | 高 | 中 | 中 | **首批试点**（内部使用） |
| 合规政策与监管变更 | 高 | 中高 | 中 | 第二批 |
| 信贷尽调报告 | 高 | 中高 | 高 | 第二批（强人审） |
| AML/反欺诈调查 | 高 | 高 | 高 | 第二批（调查员复核） |
| 客服/投顾辅助 | 中高 | 中 | 中高 | 第二批（辅助模式） |
| 量化研究/回测 | 中 | 中 | 中 | 探索型，隔离实盘 |

**组合建议**：用“1 个低风险运营场景 + 1 个高价值文档场景”做双轨试点：前者证明工程与 ROI，后者证明业务价值。两者共用同一套 RAG、工具网关、评测、日志与权限体系，避免每个场景重复造轮子。等这两条线跑通，再扩展到合规、信贷、AML 等强监管场景。

**一句话**：先做“让分析师/客户经理/调查员更快拿到可靠初稿”的 Agent，而不是“替他们签字”的 Agent。
